1. RINGKASAN PROYEK
========================================================================================
Aplikasi pemesanan makanan bergaya kiosk MCD/KFC. Dibuat dengan Windows Forms VB.NET
(.NET 10) dan database PostgreSQL di Supabase. Dikerjakan 5 orang secara paralel.

Dua mode aplikasi:
- Mode Kiosk: layar penuh dan selalu di atas. Dipakai pelanggan untuk memilih menu dan
  memesan.
- Mode Staff: jendela MDI. Staf menekan Ctrl+Alt+F12 di kiosk, login, lalu masuk. Isinya
  kasir, dapur, layar antrian, dan admin (produk, voucher, laporan, dashboard, member,
  pengguna, pengaturan, log).

Alur satu pesanan:
1. Pelanggan memilih Dine In atau Take Away, memilih menu, mengatur opsi, lalu
   memasukkan ke keranjang (A2, A3).
2. Checkout: diskon, voucher, pajak, pilih metode bayar. Pesanan disimpan dan mendapat
   nomor antrian (A3).
3. Tunai: status "Menunggu Pembayaran", pelanggan bayar di kasir lalu kasir konfirmasi
   (A4). QRIS/kartu/e-wallet (simulasi): langsung Lunas dan "Diproses" (A3).
4. Dapur melihat pesanan "Diproses" dan menandainya "Siap" (A4).
5. Layar antrian menampilkan nomor yang sedang disiapkan dan yang siap diambil (A4).
6. Pesanan diambil dan menjadi "Selesai". Datanya masuk riwayat dan laporan admin (A5).

Pembagian anggota:
A1  Fondasi, Login, MDI induk, Pengguna, Pengaturan, integrasi akhir
A2  Kiosk pelanggan: Welcome, Menu, Detail Produk, idle, rating
A3  Keranjang, Checkout, Pembayaran, Struk
A4  Kasir, Dapur, Layar Antrian, Log aktivitas
A5  Admin: Produk, Voucher, Laporan, Dashboard, Member

Nama: A1 ____________  A2 ____________  A3 ____________
      A4 ____________  A5 ____________

Materi wajib: repo https://github.com/rezaaplvv/Pemograman-Visual, yaitu Pertemuan 1-8,
11 (Windows API), dan 12 (Menu MDI). Repo itu hanya referensi, jangan di-push ke sana.
Pertemuan 9 dan 10 tidak ada di repo, jadi tidak dihitung. Kalau dosen ternyata
mewajibkannya, kabari tim. README repo punya "Kamus Sintaks" yang berguna sebagai
contekan.

Materi adalah syarat MINIMAL. Semua orang wajib memenuhinya dulu. Pengembangan di atas
materi ada di bagian 7 dan dikerjakan setelah bagian minimal milikmu jalan.

Syarat minimal setiap anggota:
- Punya minimal satu form dan satu modul sendiri.
- Punya minimal satu query ke Supabase yang berparameter.
- Validasi input dengan ErrorProvider dan TryParse.
- Penanganan error dengan Try/Catch (dan Finally bila perlu).
- Dokumentasi berformat repo materi: deskripsi, tabel kontrol, kode, pembahasan,
  kesimpulan.

2.1 Peranmu
-----------
Kamu membuat back office: mengelola produk, kategori, opsi, voucher, dan member, serta
menyajikan laporan dan dashboard dari data pesanan. Isi menu kiosk berasal dari datamu,
dan laporanmu membaca tabel pesanan milik A3 dan A4. Form milikmu banyak, jadi urutkan:
selesaikan FrmProduk, FrmVoucher, FrmLaporan (minimal) lebih dulu, baru dashboard, stok,

2.2 Form dan modul yang kamu bangun (wajib)
-------------------------------------------
FrmProduk (Forms/Admin, anak MDI)
- TabControl tabProduk dengan 3 tab: Produk, Kategori, Opsi.
- Tab Produk: dgvProduk (bsProduk), cboFilterKategori, txtCari, lalu panel input
  txtNama, cboKategori, txtHarga, txtDeskripsi, chkTersedia, chkBestSeller, txtStok,
  picFoto, btnPilihFoto, btnBaru, btnSimpan, btnHapus, errProduk.
- Validasi lengkap dengan ErrorProvider: nama wajib dan unik, kategori wajib dipilih,
  harga angka lebih dari 0 (KeyPress hanya angka, TryParse), stok kosong atau angka >=
  0.
- Upload foto: OpenFileDialog dengan filter jpg/png, tolak file lebih dari 300 KB, beri
  nama file unik (nama produk yang sudah dirapikan ditambah penanda waktu), File.Copy ke
  Asset\Produk di samping .exe di dalam Try/Catch (IOException,
  UnauthorizedAccessException). Preview dimuat lewat stream lalu clone agar file tidak
  terkunci.
- Hapus produk: konfirmasi Yes/No. Bila database menolak (PostgresException SqlState
  23503 karena produk sudah ada di pesanan), tawarkan "Nonaktifkan" yang mengubah
  tersedia menjadi False.
- Tab Kategori: dgvKategori, txtNamaKategori, nudUrutan. Kategori yang masih punya
  produk tidak boleh dihapus.
- Tab Opsi: dgvOpsi (bsOpsi) untuk produk terpilih, txtNamaOpsi, cboTipeOpsi
  (Ukuran/Addon/Pedas), txtTambahanHarga.
- Setiap simpan, ubah, atau hapus: ModCache.HapusAwalan("produk") dan ModLog.Catat
  (PRODUK_TAMBAH, PRODUK_UBAH, PRODUK_HAPUS).

FrmVoucher (Forms/Admin, anak MDI)
- Kontrol: dgvVoucher (bsVoucher), txtKode, cboJenis (Persen/Nominal), txtNilai,
  txtMinBelanja, dtpMulai, dtpAkhir, chkAktif, btnBaru, btnSimpan, btnHapus, errVoucher.
- CRUD voucher. Validasi: kode wajib dan unik, nilai lebih dari 0 (Persen maksimal 100),
  min belanja >= 0, tanggal akhir >= tanggal mulai.
- HashSet(Of String) memuat semua kode yang sudah ada untuk mencegah duplikat sebelum
  INSERT. Tetap tangkap PostgresException 23505 sebagai pengaman.
- Catat VOUCHER_UBAH.

FrmLaporan (Forms/Admin, anak MDI)
- TabControl dengan 4 tab:
  1. Riwayat Transaksi: dtpDari, dtpSampai (bawaan hari ini), cboStatus, btnTampil,
     dgvRiwayat (bsRiwayat), lblJumlah, lblOmzet. Omzet dihitung dengan loop: hanya
     pesanan status_bayar Lunas dan status_pesanan bukan Dibatalkan. Klik dua kali baris
     menampilkan detail pesanan.
  2. Rekap Kategori x Hari: array 2D Decimal (baris = kategori, kolom = hari dalam
     rentang). Isi lewat query GROUP BY kategori dan tanggal, lalu nested For. Tampilkan
     ke dgv tanpa binding (Rows.Add) lengkap dengan total baris dan total kolom, format
     Rupiah.
  3. Menu Terlaris: 10 produk dengan total qty terbanyak (query GROUP BY nama_produk
     atau Dictionary(Of String, Integer)), tampil di dgv.
  4. Ekspor: tombol Ekspor CSV pada tab aktif. SaveFileDialog, StreamWriter dalam Using
     dengan Try/Catch (IOException) dan Finally. Pemisah titik koma karena Excel
     regional Indonesia, encoding UTF-8 dengan BOM, field yang berisi titik koma atau
     tanda kutip diberi tanda kutip.
- Validasi: dtpSampai >= dtpDari (ErrorProvider), rentang maksimal 366 hari. Kirim
  dtp.Value.Date. Filter rentang: tanggal >= @dari AND tanggal < @sampai + 1 hari.
- Filter status pada riwayat memakai BindingSource.Filter bila data sudah dimuat.

ModLaporan (Modul)
- Semua query laporan (riwayat, rekap, terlaris, ringkasan dashboard) di sini. Modul
  tidak menampilkan MessageBox.

2.5 Pengembangan milikmu (butir 7, 8, 12)
-----------------------------------------
#7 Stok otomatis (P1)
- Kolom stok di FrmProduk: kosong berarti tidak dilacak. Tambahkan tombol "Tambah Stok"
  cepat (+10, +50). Aturan: stok menjadi 0 otomatis membuat tersedia = False, stok naik

- DataGridView memakai CellFormatting: stok kurang dari atau sama dengan ambang_stok
  (ModPengaturan, bawaan 5) berwarna kuning, stok 0 berwarna merah.
- Titik temu: A3 mengurangi stok di transaksi pesanan, A4 mengembalikan stok saat
  pembatalan, A2 menampilkan "HABIS". Opsional: sediakan ModLaporan.JumlahStokMenipis()

#8 Dashboard dan grafik (P1)
- FrmDashboard (anak MDI): kartu ringkasan hari ini (pendapatan, jumlah pesanan,

  batang penjualan 7 hari terakhir, dan top 5 menu terlaris.
- Kontrol Chart bawaan .NET Framework tidak ikut di WinForms .NET modern, jadi grafik
  digambar sendiri dengan GDI+ lewat UserControl GrafikBatang
  (Controls/GrafikBatang.vb): event Paint, Graphics.FillRectangle, DrawString,

- Muat data lewat versi Async (AmbilDataAsync dari A1) dan refresh tiap 30 detik memakai
  Timer. UI tidak boleh membeku saat memuat.

#12 Member dan poin (P2)
- FrmMember (anak MDI, bisa dibuka Admin dan Kasir): dgvMember (bsMember), txtNoHp

4.2 Konvensi
------------
- Teknologi: VB.NET, Windows Forms, target net10.0-windows, format solution .slnx.
  Option Strict On diatur di .vbproj oleh A1. Paket NuGet: Npgsql dan
  Microsoft.Extensions.Configuration.Json. Satu-satunya paket tambahan untuk
  pengembangan adalah QRCoder (dipakai A3). Samakan versi Visual Studio dan SDK .NET
  dengan yang dipakai di materi.
- Prefix kontrol dari materi: btn, txt, lbl, cbo, dgv, lst, bs, err, pic, chk, tmr.
  Tambahan yang disepakati: pnl, flp, tab, mnu, nud, dtp, rdo, grp.
- Form berawalan Frm, modul berawalan Mod. Class model memakai PascalCase tanpa prefix.
- Class model memakai Public Property, bukan field public.
- Modul data dan modul hitung tidak menampilkan MessageBox. Error dilempar ke pemanggil,
  lalu form yang menangkapnya dengan Try/Catch dan menampilkan pesan ramah.
- Semua query berparameter. Parameter dikirim lewat Dictionary(Of String, Object) dengan
  kunci tanpa tanda @. Dilarang menyambung input pengguna langsung ke teks SQL.
- Pesan ke pengguna memakai Bahasa Indonesia yang singkat dan jelas. Jangan tampilkan
  stack trace ke pelanggan.
- Format uang selalu lewat ModFormat.Rupiah. Status, metode bayar, dan peran selalu
  lewat class konstanta, jangan menulis string manual.
- Waktu: kolom waktu pesanan disimpan dalam WIB oleh SQL, yaitu (now() at time zone
  'Asia/Jakarta'). Server Supabase memakai UTC, jadi tanpa ini nomor antrian dan laporan
  harian akan salah jam. Jangan kirim DateTime.Now atau DateTime.UtcNow ke kolom waktu
  pesanan. Untuk filter tanggal dari DateTimePicker kirim dtp.Value.Date.
- Saat debug (Debugger.IsAttached), jangan aktifkan TopMost dan layar penuh supaya
  Visual Studio tetap bisa dipakai.
- Jangan mengedit file .Designer.vb dengan tangan kecuali terpaksa.
- Event handler dibuat pendek. Query dan perhitungan ditaruh di modul.

12. RISIKO DAN TIPS
========================================================================================
- Project Supabase paket Free dijeda otomatis kalau aktivitas database terlalu sedikit
  selama seminggu. Pastikan project aktif sebelum demo. Simpan skema.sql dan seed.sql
  supaya database bisa dibuat ulang dengan cepat.
- Koneksi dari rumah bisa gagal karena koneksi langsung Supabase biasanya hanya IPv6.
  Pakai connection string "Session pooler" dari dashboard (menu Connect). Bukan
  "Transaction pooler".
- Password database milik repo materi sudah terlanjur terbuka di repo publik. Jangan
  dipakai ulang. Sebaiknya beri tahu pemilik repo untuk me-reset password-nya.
- Aktifkan RLS (Row Level Security) di semua tabel tanpa membuat policy, supaya tabel
  tidak terbuka lewat API publik Supabase. Koneksi Npgsql memakai user postgres dan
  tidak terpengaruh RLS.
- Jangan pernah memblok UI thread. Di versi async jangan pakai .Result atau .Wait().
  Pakai Async Sub dan Await.
- Image.FromFile mengunci file. Selalu ambil gambar lewat ModProduk.AmbilGambar (membaca
  lewat stream lalu clone) supaya file bisa diganti.
- Npgsql menolak DateTime ber-Kind UTC untuk kolom timestamp tanpa zona. Kirim
  dtp.Value.Date dan biarkan SQL mengisi waktu.
- Hotkey Ctrl+Alt+F12 bisa gagal terdaftar bila dipakai aplikasi lain. DaftarHotkey
  mengembalikan False, maka siapkan cadangan: klik 5 kali cepat pada logo di pojok
  FrmWelcome membuka login.
- Hapus data yang sudah dipakai di pesanan akan ditolak database (kode 23503). Tangkap
  PostgresException dan tawarkan "Nonaktifkan" sebagai gantinya. Kode duplikat unik
  adalah 23505.
- Di VB, Dictionary dan List dalam modul bersifat shared dan hidup selama aplikasi
  jalan. Bersihkan saat Kosongkan/Keluar supaya data pesanan lama tidak bocor ke
  pelanggan berikutnya.
- Merge besar di akhir adalah sumber masalah terbesar. Merge kecil dan sering.
