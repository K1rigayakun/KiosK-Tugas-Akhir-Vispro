1. RINGKASAN PROYEK
========================================================================================
Aplikasi pemesanan makanan bergaya kiosk MCD/KFC. Dibuat dengan Windows Forms VB.NET
(.NET 10) dan database PostgreSQL di Supabase. Dikerjakan 5 orang secara paralel.

Dua mode aplikasi:
- Mode Kiosk: layar penuh dan selalu di atas. Dipakai pelanggan untuk memilih menu dan
  memesan.
- Mode Staff: jendela MDI. Staf menekan Ctrl+Alt+F12 di kiosk, login, lalu masuk. Isinya
  kasir, dapur, layar antrian, dan admin (produk, voucher, laporan, dashboard, member,
  pengguna, pengaturan, log).

Alur satu pesanan:
1. Pelanggan memilih Dine In atau Take Away, memilih menu, mengatur opsi, lalu
   memasukkan ke keranjang (A2, A3).
2. Checkout: diskon, voucher, pajak, pilih metode bayar. Pesanan disimpan dan mendapat
   nomor antrian (A3).
3. Tunai: status "Menunggu Pembayaran", pelanggan bayar di kasir lalu kasir konfirmasi
   (A4). QRIS/kartu/e-wallet (simulasi): langsung Lunas dan "Diproses" (A3).
4. Dapur melihat pesanan "Diproses" dan menandainya "Siap" (A4).
5. Layar antrian menampilkan nomor yang sedang disiapkan dan yang siap diambil (A4).
6. Pesanan diambil dan menjadi "Selesai". Datanya masuk riwayat dan laporan admin (A5).

Pembagian anggota:
A1  Fondasi, Login, MDI induk, Pengguna, Pengaturan, integrasi akhir
A2  Kiosk pelanggan: Welcome, Menu, Detail Produk, idle, rating
A3  Keranjang, Checkout, Pembayaran, Struk
A4  Kasir, Dapur, Layar Antrian, Log aktivitas
A5  Admin: Produk, Voucher, Laporan, Dashboard, Member

Nama: A1 ____________  A2 ____________  A3 ____________
      A4 ____________  A5 ____________

Materi wajib: repo https://github.com/rezaaplvv/Pemograman-Visual, yaitu Pertemuan 1-8,
11 (Windows API), dan 12 (Menu MDI). Repo itu hanya referensi, jangan di-push ke sana.
Pertemuan 9 dan 10 tidak ada di repo, jadi tidak dihitung. Kalau dosen ternyata
mewajibkannya, kabari tim. README repo punya "Kamus Sintaks" yang berguna sebagai
contekan.

Materi adalah syarat MINIMAL. Semua orang wajib memenuhinya dulu. Pengembangan di atas
materi ada di bagian 7 dan dikerjakan setelah bagian minimal milikmu jalan.

Syarat minimal setiap anggota:
- Punya minimal satu form dan satu modul sendiri.
- Punya minimal satu query ke Supabase yang berparameter.
- Validasi input dengan ErrorProvider dan TryParse.
- Penanganan error dengan Try/Catch (dan Finally bila perlu).
- Dokumentasi berformat repo materi: deskripsi, tabel kontrol, kode, pembahasan,
  kesimpulan.

2.3 Form dan modul yang kamu bangun (wajib)
-------------------------------------------
FrmLogin (Forms/Umum)
- Kontrol: txtUsername, txtPassword (PasswordChar "*"), btnMasuk, btnBatal, lblPesan,
  errLogin (ErrorProvider), tmrKunci (Timer).
- Kedua kolom wajib diisi (ErrorProvider). Query berparameter ke tabel pengguna
  (username dan aktif = true), lalu bandingkan hash password. Seluruh proses dibungkus
  Try/Catch/Finally: koneksi gagal menghasilkan pesan ramah, bukan crash.
- Saat sukses: isi ModSesi, ModLog.Catat("LOGIN"), DialogResult.OK. Peran diambil dari
  database, bukan dipilih pengguna.
- Versi minimal memakai hash SHA256. Butir pengembangan #4 menggantinya.

FrmUtama (MDI induk, Forms/Umum)
- IsMdiContainer = True. MenuStrip: Transaksi (Kasir), Dapur (Dapur, Layar Antrian),
  Master (Produk, Voucher, Member), Laporan (Laporan, Dashboard), Sistem (Pengguna,
  Pengaturan, Log, Kembali ke Kiosk, Keluar).
- Menu tampil sesuai peran lewat ModSesi.BolehAkses. Admin: semua menu. Kasir: Kasir,
  Dapur, Layar Antrian, Member.
- Membuka form anak: cek dulu apakah sudah terbuka (For Each pada MdiChildren). Bila
  sudah, cukup aktifkan. Bila belum, set MdiParent lalu Show. FrmAntrian dibuka sebagai
  jendela biasa karena layar penuh.
- Menu Window: Cascade, Tile Horizontal, Tile Vertical, Tutup Semua (LayoutMdi).
- StatusStrip: nama dan peran pengguna, jam (Timer), status koneksi database
  (ModDatabase.TesKoneksi dipanggil async).
- "Kembali ke Kiosk": tutup semua form anak, ModSesi.Keluar, ModLog.Catat("LOGOUT"),
  lalu tampilkan lagi FrmWelcome.

FrmPengguna (Forms/Umum)
- Kontrol: dgvPengguna (bsPengguna), txtUsername, txtNama, txtPassword, cboPeran
  (DropDownList), chkAktif, txtCari, btnTambah, btnSimpan, btnNonaktifkan,
  btnResetPassword, errPengguna.
- CRUD akun Admin dan Kasir. Akun dinonaktifkan, bukan dihapus. Username harus unik (cek
  ke database dan tampilkan lewat ErrorProvider). Password minimal 6 karakter. Pencarian
  memakai BindingSource.Filter.
- Aturan: tidak boleh menonaktifkan atau menurunkan peran akun yang sedang login. Setiap
  aksi dicatat ModLog.Catat("PENGGUNA_UBAH").

Modul inti
- ModDatabase: baca appsettings.json lewat Microsoft.Extensions.Configuration.Json,
  BukaKoneksi, TesKoneksi.
- ModFunction: AmbilData, EksekusiData, EksekusiScalar berparameter, memakai Using.
  Modul tidak menampilkan MessageBox, error dilempar ke pemanggil.
- ModValidasi: WajibIsi, BacaAngka (TryParse plus ErrorProvider), HanyaAngka (untuk
  KeyPress).
- ModFormat: Rupiah dan Durasi. Gunakan CultureInfo("id-ID") untuk format Rupiah.
- ModSesi: data pengguna yang sedang login dan BolehAkses.
- ModWindowsApi: SelaluDiAtas (SetWindowPos dengan HWND_TOPMOST), DaftarHotkey dan
  BatalHotkey (RegisterHotKey dan UnregisterHotKey), Bunyi (MessageBeep), WaktuAktif
  (GetTickCount64). Salin pola dari proyek Pertemuan 11 (DemoWindowsApi), pelajari dulu.
- Konstanta dan class model sesuai bagian 5.3 dan 6.1.

2.5 Skema SQL (dijalankan di SQL Editor Supabase)
-------------------------------------------------
Simpan sebagai Database/skema.sql. Urutan sudah memperhatikan relasi.
create table kategori (
  id_kategori serial primary key,
  nama varchar(50) not null unique,
  urutan int not null default 0
);
create table produk (
  id_produk serial primary key,
  id_kategori int not null references kategori(id_kategori),
  nama varchar(100) not null,
  deskripsi text,
  harga numeric(12,0) not null check (harga >= 0),
  gambar varchar(150),
  tersedia boolean not null default true,
  best_seller boolean not null default false,
  stok int,
  dibuat_pada timestamp not null default (now() at time zone 'Asia/Jakarta')
);
create table opsi_produk (
  id_opsi serial primary key,
  id_produk int not null references produk(id_produk) on delete cascade,
  nama_opsi varchar(50) not null,
  tipe varchar(20) not null check (tipe in ('Ukuran','Addon','Pedas')),
  tambahan_harga numeric(12,0) not null default 0
);
create table pengguna (
  id_pengguna serial primary key,
  username varchar(50) not null unique,
  password_hash text not null,
  nama varchar(100) not null,
  role varchar(20) not null check (role in ('Admin','Kasir')),
  aktif boolean not null default true
);
create table member (
  id_member serial primary key,
  no_hp varchar(20) not null unique,
  nama varchar(100) not null,
  poin int not null default 0
);
create table voucher (
  kode varchar(30) primary key,
  jenis varchar(10) not null check (jenis in ('Persen','Nominal')),
  nilai numeric(12,2) not null check (nilai > 0),
  min_belanja numeric(12,0) not null default 0,
  tgl_mulai date not null,
  tgl_akhir date not null,
  aktif boolean not null default true,
  check (tgl_akhir >= tgl_mulai)
);
create table pesanan (
  id_pesanan serial primary key,
  no_antrian int not null,
  tipe_makan varchar(20) not null,
  tanggal timestamp not null default (now() at time zone 'Asia/Jakarta'),
  subtotal numeric(12,0) not null,
  diskon numeric(12,0) not null default 0,
  pajak numeric(12,0) not null default 0,
  total numeric(12,0) not null,
  metode_bayar varchar(20) not null,
  status_bayar varchar(10) not null default 'Belum',
  status_pesanan varchar(30) not null default 'Menunggu Pembayaran',
  id_kasir int references pengguna(id_pengguna),
  kode_voucher varchar(30) references voucher(kode),
  id_member int references member(id_member),
  poin_dipakai int not null default 0,
  poin_didapat int not null default 0,
  uang_bayar numeric(12,0),
  kembalian numeric(12,0),
  waktu_diproses timestamp,
  waktu_siap timestamp
);
create unique index ux_pesanan_antrian_harian on pesanan ((tanggal::date), no_antrian);
create index ix_pesanan_status on pesanan (status_pesanan, tanggal);
create table detail_pesanan (
  id_detail serial primary key,
  id_pesanan int not null references pesanan(id_pesanan) on delete cascade,
  id_produk int not null references produk(id_produk),
  nama_produk varchar(100) not null,
  qty int not null check (qty > 0),
  harga_satuan numeric(12,0) not null,
  opsi_dipilih text,
  catatan varchar(200),
  subtotal numeric(12,0) not null
);
create table log_aktivitas (
  id_log bigserial primary key,
  waktu timestamp not null default (now() at time zone 'Asia/Jakarta'),
  id_pengguna int references pengguna(id_pengguna),
  aksi varchar(50) not null,
  keterangan text
);
create table pengaturan (
  kunci varchar(50) primary key,
  nilai text not null
);
create table rating_pesanan (
  id_pesanan int primary key references pesanan(id_pesanan) on delete cascade,
  bintang int not null check (bintang between 1 and 5),
  komentar varchar(300)
);
create table banner_promo (
  id_banner serial primary key,
  judul varchar(100) not null,
  gambar varchar(150) not null,
  urutan int not null default 0,
  aktif boolean not null default true
);

2.6 Pengembangan milikmu (butir 1, 2, 4, 9, 15)
-----------------------------------------------
#1 Tema kiosk modern (P1)
- ModTema berisi palet (merah, kuning, putih, abu gelap), font Segoe UI, dan metode
  TerapkanForm, TombolUtama, TombolSekunder. Tombol di kiosk setinggi minimal 56 px,
  flat, dengan efek hover lewat MouseEnter dan MouseLeave.
- Versi stub di Fase 0 cukup mengembalikan warna dasar. Versi final dikerjakan di Fase
  1. Nama anggota dan metode tidak berubah, hanya nilainya, jadi form lain tidak perlu
  diubah.

#2 Database responsif: async dan cache (P1)
- Tambahkan versi Async di ModFunction (OpenAsync, ExecuteReaderAsync, lalu
  DataTable.Load).
- ModCache menyimpan hasil query di Dictionary dengan waktu kedaluwarsa. Metode Ambil(Of
  T), Hapus, HapusAwalan. TTL: kategori 300 detik, produk 60 detik.
- Beri contoh pemakaian di Dokumentasi agar anggota lain memakai Async Sub dan Await,
  bukan .Result atau .Wait().

#4 Login lebih aman (P1)
- Ganti SHA256 menjadi PBKDF2 memakai Rfc2898DeriveBytes.Pbkdf2 (SHA256, salt acak 16
  byte, minimal 100.000 iterasi). Simpan dalam satu string:
  pbkdf2$iterasi$salt(base64)$hash(base64). Bandingkan dengan
  CryptographicOperations.FixedTimeEquals.
- Hash lama (SHA256) tetap diterima satu kali, lalu otomatis diganti ke format baru
  setelah login berhasil.
- Batas percobaan: 5 kali gagal berturut-turut mengunci tombol Masuk selama 30 detik.
  Hitung mundur tampil di lblPesan lewat tmrKunci. Catat LOGIN_GAGAL di ModLog (jangan
  menyimpan password yang diketik).
- FrmPengguna memakai format baru untuk tambah akun dan reset password.

#9 Build .exe siap demo (P1)
- Perintah: dotnet publish -c Release -r win-x64 --self-contained true
  -p:PublishSingleFile=true. Jangan aktifkan trimming.
- appsettings.json diletakkan di samping .exe (tidak di-embed karena berisi password).
  Folder Asset ikut disalin ke samping .exe.
- Beri ikon aplikasi (.ico) dan isi judul, versi. Tes di komputer lain yang tidak punya
  Visual Studio. Tulis langkahnya di Dokumentasi/Cara-Build.md.

#15 Pengaturan aplikasi (P2)
- FrmPengaturan (Forms/Umum, anak MDI, hanya Admin) mengedit kunci di bagian 6.7.
  Validasi tiap kolom dengan TryParse dan rentang wajar (contoh: pajak 0-30, idle 15-600
  detik). Simpan lewat ModPengaturan.Simpan dan catat PENGATURAN_UBAH.
- ModPengaturan memuat semua kunci ke Dictionary saat Sub Main. Bila database gagal
  dibaca, gunakan nilai bawaan agar kiosk tetap jalan.

4.2 Konvensi
------------
- Teknologi: VB.NET, Windows Forms, target net10.0-windows, format solution .slnx.
  Option Strict On diatur di .vbproj oleh A1. Paket NuGet: Npgsql dan
  Microsoft.Extensions.Configuration.Json. Satu-satunya paket tambahan untuk
  pengembangan adalah QRCoder (dipakai A3). Samakan versi Visual Studio dan SDK .NET
  dengan yang dipakai di materi.
- Prefix kontrol dari materi: btn, txt, lbl, cbo, dgv, lst, bs, err, pic, chk, tmr.
  Tambahan yang disepakati: pnl, flp, tab, mnu, nud, dtp, rdo, grp.
- Form berawalan Frm, modul berawalan Mod. Class model memakai PascalCase tanpa prefix.
- Class model memakai Public Property, bukan field public.
- Modul data dan modul hitung tidak menampilkan MessageBox. Error dilempar ke pemanggil,
  lalu form yang menangkapnya dengan Try/Catch dan menampilkan pesan ramah.
- Semua query berparameter. Parameter dikirim lewat Dictionary(Of String, Object) dengan
  kunci tanpa tanda @. Dilarang menyambung input pengguna langsung ke teks SQL.
- Pesan ke pengguna memakai Bahasa Indonesia yang singkat dan jelas. Jangan tampilkan
  stack trace ke pelanggan.
- Format uang selalu lewat ModFormat.Rupiah. Status, metode bayar, dan peran selalu
  lewat class konstanta, jangan menulis string manual.
- Waktu: kolom waktu pesanan disimpan dalam WIB oleh SQL, yaitu (now() at time zone
  'Asia/Jakarta'). Server Supabase memakai UTC, jadi tanpa ini nomor antrian dan laporan
  harian akan salah jam. Jangan kirim DateTime.Now atau DateTime.UtcNow ke kolom waktu
  pesanan. Untuk filter tanggal dari DateTimePicker kirim dtp.Value.Date.
- Saat debug (Debugger.IsAttached), jangan aktifkan TopMost dan layar penuh supaya
  Visual Studio tetap bisa dipakai.
- Jangan mengedit file .Designer.vb dengan tangan kecuali terpaksa.
- Event handler dibuat pendek. Query dan perhitungan ditaruh di modul.

12. RISIKO DAN TIPS
========================================================================================
- Project Supabase paket Free dijeda otomatis kalau aktivitas database terlalu sedikit
  selama seminggu. Pastikan project aktif sebelum demo. Simpan skema.sql dan seed.sql
  supaya database bisa dibuat ulang dengan cepat.
- Koneksi dari rumah bisa gagal karena koneksi langsung Supabase biasanya hanya IPv6.
  Pakai connection string "Session pooler" dari dashboard (menu Connect). Bukan
  "Transaction pooler".
- Password database milik repo materi sudah terlanjur terbuka di repo publik. Jangan
  dipakai ulang. Sebaiknya beri tahu pemilik repo untuk me-reset password-nya.
- Aktifkan RLS (Row Level Security) di semua tabel tanpa membuat policy, supaya tabel
  tidak terbuka lewat API publik Supabase. Koneksi Npgsql memakai user postgres dan
  tidak terpengaruh RLS.
- Jangan pernah memblok UI thread. Di versi async jangan pakai .Result atau .Wait().
  Pakai Async Sub dan Await.
- Image.FromFile mengunci file. Selalu ambil gambar lewat ModProduk.AmbilGambar (membaca
  lewat stream lalu clone) supaya file bisa diganti.
- Npgsql menolak DateTime ber-Kind UTC untuk kolom timestamp tanpa zona. Kirim
  dtp.Value.Date dan biarkan SQL mengisi waktu.
- Hotkey Ctrl+Alt+F12 bisa gagal terdaftar bila dipakai aplikasi lain. DaftarHotkey
  mengembalikan False, maka siapkan cadangan: klik 5 kali cepat pada logo di pojok
  FrmWelcome membuka login.
- Hapus data yang sudah dipakai di pesanan akan ditolak database (kode 23503). Tangkap
  PostgresException dan tawarkan "Nonaktifkan" sebagai gantinya. Kode duplikat unik
  adalah 23505.
- Di VB, Dictionary dan List dalam modul bersifat shared dan hidup selama aplikasi
  jalan. Bersihkan saat Kosongkan/Keluar supaya data pesanan lama tidak bocor ke
  pelanggan berikutnya.
- Merge besar di akhir adalah sumber masalah terbesar. Merge kecil dan sering.
