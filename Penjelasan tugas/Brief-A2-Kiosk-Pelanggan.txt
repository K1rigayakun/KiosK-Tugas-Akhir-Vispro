1. RINGKASAN PROYEK
========================================================================================
Aplikasi pemesanan makanan bergaya kiosk MCD/KFC. Dibuat dengan Windows Forms VB.NET
(.NET 10) dan database PostgreSQL di Supabase. Dikerjakan 5 orang secara paralel.

Dua mode aplikasi:
- Mode Kiosk: layar penuh dan selalu di atas. Dipakai pelanggan untuk memilih menu dan
  memesan.
- Mode Staff: jendela MDI. Staf menekan Ctrl+Alt+F12 di kiosk, login, lalu masuk. Isinya
  kasir, dapur, layar antrian, dan admin (produk, voucher, laporan, dashboard, member,
  pengguna, pengaturan, log).

Alur satu pesanan:
1. Pelanggan memilih Dine In atau Take Away, memilih menu, mengatur opsi, lalu
   memasukkan ke keranjang (A2, A3).
2. Checkout: diskon, voucher, pajak, pilih metode bayar. Pesanan disimpan dan mendapat
   nomor antrian (A3).
3. Tunai: status "Menunggu Pembayaran", pelanggan bayar di kasir lalu kasir konfirmasi
   (A4). QRIS/kartu/e-wallet (simulasi): langsung Lunas dan "Diproses" (A3).
4. Dapur melihat pesanan "Diproses" dan menandainya "Siap" (A4).
5. Layar antrian menampilkan nomor yang sedang disiapkan dan yang siap diambil (A4).
6. Pesanan diambil dan menjadi "Selesai". Datanya masuk riwayat dan laporan admin (A5).

Pembagian anggota:
A1  Fondasi, Login, MDI induk, Pengguna, Pengaturan, integrasi akhir
A2  Kiosk pelanggan: Welcome, Menu, Detail Produk, idle, rating
A3  Keranjang, Checkout, Pembayaran, Struk
A4  Kasir, Dapur, Layar Antrian, Log aktivitas
A5  Admin: Produk, Voucher, Laporan, Dashboard, Member

Nama: A1 ____________  A2 ____________  A3 ____________
      A4 ____________  A5 ____________

Materi wajib: repo https://github.com/rezaaplvv/Pemograman-Visual, yaitu Pertemuan 1-8,
11 (Windows API), dan 12 (Menu MDI). Repo itu hanya referensi, jangan di-push ke sana.
Pertemuan 9 dan 10 tidak ada di repo, jadi tidak dihitung. Kalau dosen ternyata
mewajibkannya, kabari tim. README repo punya "Kamus Sintaks" yang berguna sebagai
contekan.

Materi adalah syarat MINIMAL. Semua orang wajib memenuhinya dulu. Pengembangan di atas
materi ada di bagian 7 dan dikerjakan setelah bagian minimal milikmu jalan.

Syarat minimal setiap anggota:
- Punya minimal satu form dan satu modul sendiri.
- Punya minimal satu query ke Supabase yang berparameter.
- Validasi input dengan ErrorProvider dan TryParse.
- Penanganan error dengan Try/Catch (dan Finally bila perlu).
- Dokumentasi berformat repo materi: deskripsi, tabel kontrol, kode, pembahasan,
  kesimpulan.

2.1 Peranmu
-----------
Kamu membuat sisi pelanggan: layar awal, daftar menu, detail produk dengan opsi, serta
mekanisme kiosk (layar penuh, selalu di atas, reset otomatis saat tidak ada aktivitas).
Tampilan kiosk adalah wajah aplikasi saat demo, jadi tampilannya penting. Kamu
bergantung pada A1 (kerangka dan ModWindowsApi) dan berhubungan dengan A3 lewat

2.2 Form dan modul yang kamu bangun (wajib)
-------------------------------------------
FrmWelcome (Forms/Kiosk)
- Kontrol: pnlLatar, lblJudul, btnDineIn, btnTakeAway, picLogo.
- FormBorderStyle None, WindowState Maximized, selalu di atas lewat
  ModWindowsApi.SelaluDiAtas (lewati saat Debugger.IsAttached).
- Memilih Dine In atau Take Away mengisi ModKeranjang.TipeMakan (pakai konstanta
  TipeMakan), lalu membuka FrmMenu dan menyembunyikan FrmWelcome.
- Hotkey staff Ctrl+Alt+F12: daftarkan di FrmWelcome dengan
  ModWindowsApi.DaftarHotkey(Me.Handle, 1, ...), tangkap WM_HOTKEY (&H312) pada override
  WndProc, lalu ShowDialog FrmLogin. Jika login OK: sembunyikan kiosk (matikan TopMost),
  ModIdle.Berhenti, buka FrmUtama. Saat FrmUtama tertutup: tampilkan kiosk lagi,
  aktifkan TopMost dan ModIdle.Mulai, kosongkan keranjang.
- FrmWelcome TIDAK pernah ditutup selama aplikasi jalan, hanya Hide dan Show, supaya
  hotkey tetap hidup. Batalkan hotkey pada FormClosing.
- Cadangan bila DaftarHotkey mengembalikan False: klik 5 kali cepat pada picLogo membuka
  login.

FrmMenu (Forms/Kiosk)
- Kontrol: tabKategori (atau barisan tombol kategori), flpProduk (FlowLayoutPanel
  AutoScroll), txtCari, lblJumlahItem, lblTotal, btnKeranjang, btnBatalPesanan, bsProduk
  (BindingSource), errMenu.
- Muat kategori dari ModProduk.AmbilKategori (tab "Semua" ditambah satu per kategori).
  Muat produk ke DataTable dan ikat ke bsProduk.
- Pencarian dan kategori memakai bsProduk.Filter, contoh: "nama LIKE '%kata%'" digabung
  dengan filter kategori. Tanda kutip tunggal pada input diganti dua kali lipat
  (Replace("'", "''")) supaya filter tidak error.
- Setiap filter berubah: kosongkan flpProduk (Dispose kartu lama) lalu bangun ulang
  kartu dengan For Each pada bsProduk.List (DataRowView).
- Kartu produk: gambar (PictureBox SizeMode Zoom dari ModProduk.AmbilGambar), nama,
  harga (ModFormat.Rupiah), label "Best Seller" bila best_seller, dan label "HABIS"
  (kartu dinonaktifkan) bila tersedia = False atau stok = 0.
- Klik kartu membuka FrmDetailProduk. Tombol Keranjang membuka FrmKeranjang (A3). Label
  jumlah item dan total mengikuti event ModKeranjang.KeranjangBerubah.
- Batal Pesanan: konfirmasi MessageBox Yes/No, ModKeranjang.Kosongkan, kembali ke
  FrmWelcome.

FrmDetailProduk(idProduk) (Forms/Kiosk)
- Kontrol: picProduk, lblNama, lblDeskripsi, lblHarga, grpUkuran (RadioButton dibuat
  dengan loop dari opsi tipe Ukuran, bawaan pilihan pertama), flpAddon (CheckBox dari
  opsi tipe Addon), grpPedas (RadioButton dari tipe Pedas), txtCatatan (MaxLength 100),
  txtQty dengan tombol - dan +, lblHargaTotal, btnTambah, btnBatal, errDetail.
- Panel opsi yang tidak dimiliki produk disembunyikan.
- Qty: KeyPress hanya angka (ModValidasi.HanyaAngka), TryParse, rentang 1-20, pesan
  lewat ErrorProvider.
- Harga total dihitung langsung saat opsi berubah: (harga + tambahan ukuran + tambahan
  addon) x qty, dihitung dengan loop.
- Tambah: bangun ItemKeranjang (OpsiDipilih berupa teks ringkas, contoh "Large, Keju,
  Pedas 2"), panggil ModKeranjang.Tambah, lalu DialogResult.OK.

FrmIdle (Forms/Kiosk) dan ModIdle (Modul)
- ModIdle memasang IMessageFilter pada Application (Application.AddMessageFilter) yang
  mencatat waktu aktivitas terakhir dari pesan mouse dan keyboard memakai
  ModWindowsApi.WaktuAktif (GetTickCount64). Dengan begitu form milik A3 juga otomatis
  terhitung aktif.
- Timer di dalam ModIdle memeriksa selisih waktu. Batas diambil dari ModPengaturan
  "idle_detik" (bawaan 60). Saat batas tercapai, tampilkan FrmIdle ("Masih di sana?")
  dengan hitung mundur 10 detik dan tombol Lanjutkan. Bila habis, raise Event Habis.
- Handler Habis di FrmWelcome: tutup semua form kiosk yang terbuka (For Each pada
  salinan Application.OpenForms, kecuali FrmWelcome dan FrmUtama),
  ModKeranjang.Kosongkan, tampilkan FrmWelcome.
- ModIdle tidak aktif saat mode staff.

ModProduk (Modul)
- AmbilKategori, AmbilProduk, AmbilOpsi (bagian 6.3). Query berparameter, hasil
  dibungkus ModCache setelah #2 dari A1 siap.
- AmbilGambar(namaFile): baca file dari Asset\Produk lewat FileStream lalu clone supaya
  file tidak terkunci, simpan di Dictionary(Of String, Image) sebagai cache. Bila file
  tidak ada, kembalikan gambar placeholder yang digambar dengan GDI+.

2.5 Pengembangan milikmu (butir 5, 16, 17, 18)
----------------------------------------------
#5 Kartu produk kustom (P1)
- Versi minimal ProdukCard adalah UserControl gabungan PictureBox dan Label. Versi P1
  menggambar sendiri lewat OnPaint: sudut membulat (GraphicsPath), bayangan tipis, efek
  hover dan tekan (MouseEnter, MouseLeave, MouseDown), badge Best Seller, dan tampilan
  abu-abu untuk produk Habis.
- Set DoubleBuffered = True supaya tidak berkedip. Property Produk dan Event
  Dipilih(produk). Gambar diambil dari cache ModProduk.AmbilGambar dan tidak di-Dispose
  oleh kartu. Warna dan font dari ModTema.

#16 Dua bahasa ID/EN (P3)
- ModBahasa berisi dua Dictionary(Of String, String) untuk ID dan EN, fungsi T(kunci),
  property Bahasa, dan Event BahasaBerubah. Tombol toggle di pojok FrmWelcome dan
  FrmMenu. Semua teks tetap (bukan nama produk) memakai T(...). Bahasa awal dari
  ModPengaturan "bahasa_default".
- A3 mengirim daftar teks form miliknya (kunci, teks ID, teks EN) lewat chat, kamu yang
  memasukkannya ke ModBahasa.

#17 Banner promo (P3)
- pnlBanner di FrmWelcome menampilkan slide dari tabel banner_promo (aktif = true, urut
  berdasarkan urutan), gambar dari Asset\Banner. Timer 4 detik berganti slide dengan
  loop indeks. Bila data kosong, panel disembunyikan.

#18 Rating pesanan (P3)
- FrmRating(idPesanan): lima bintang yang bisa diklik, komentar opsional (MaxLength
  300), tombol Kirim dan Lewati. Simpan dengan INSERT ... ON CONFLICT (id_pesanan) DO
  UPDATE ke rating_pesanan. Form ini dibuka A3 dari FrmStruk setelah pesanan selesai.

4.2 Konvensi
------------
- Teknologi: VB.NET, Windows Forms, target net10.0-windows, format solution .slnx.
  Option Strict On diatur di .vbproj oleh A1. Paket NuGet: Npgsql dan
  Microsoft.Extensions.Configuration.Json. Satu-satunya paket tambahan untuk
  pengembangan adalah QRCoder (dipakai A3). Samakan versi Visual Studio dan SDK .NET
  dengan yang dipakai di materi.
- Prefix kontrol dari materi: btn, txt, lbl, cbo, dgv, lst, bs, err, pic, chk, tmr.
  Tambahan yang disepakati: pnl, flp, tab, mnu, nud, dtp, rdo, grp.
- Form berawalan Frm, modul berawalan Mod. Class model memakai PascalCase tanpa prefix.
- Class model memakai Public Property, bukan field public.
- Modul data dan modul hitung tidak menampilkan MessageBox. Error dilempar ke pemanggil,
  lalu form yang menangkapnya dengan Try/Catch dan menampilkan pesan ramah.
- Semua query berparameter. Parameter dikirim lewat Dictionary(Of String, Object) dengan
  kunci tanpa tanda @. Dilarang menyambung input pengguna langsung ke teks SQL.
- Pesan ke pengguna memakai Bahasa Indonesia yang singkat dan jelas. Jangan tampilkan
  stack trace ke pelanggan.
- Format uang selalu lewat ModFormat.Rupiah. Status, metode bayar, dan peran selalu
  lewat class konstanta, jangan menulis string manual.
- Waktu: kolom waktu pesanan disimpan dalam WIB oleh SQL, yaitu (now() at time zone
  'Asia/Jakarta'). Server Supabase memakai UTC, jadi tanpa ini nomor antrian dan laporan
  harian akan salah jam. Jangan kirim DateTime.Now atau DateTime.UtcNow ke kolom waktu
  pesanan. Untuk filter tanggal dari DateTimePicker kirim dtp.Value.Date.
- Saat debug (Debugger.IsAttached), jangan aktifkan TopMost dan layar penuh supaya
  Visual Studio tetap bisa dipakai.
- Jangan mengedit file .Designer.vb dengan tangan kecuali terpaksa.
- Event handler dibuat pendek. Query dan perhitungan ditaruh di modul.

12. RISIKO DAN TIPS
========================================================================================
- Project Supabase paket Free dijeda otomatis kalau aktivitas database terlalu sedikit
  selama seminggu. Pastikan project aktif sebelum demo. Simpan skema.sql dan seed.sql
  supaya database bisa dibuat ulang dengan cepat.
- Koneksi dari rumah bisa gagal karena koneksi langsung Supabase biasanya hanya IPv6.
  Pakai connection string "Session pooler" dari dashboard (menu Connect). Bukan
  "Transaction pooler".
- Password database milik repo materi sudah terlanjur terbuka di repo publik. Jangan
  dipakai ulang. Sebaiknya beri tahu pemilik repo untuk me-reset password-nya.
- Aktifkan RLS (Row Level Security) di semua tabel tanpa membuat policy, supaya tabel
  tidak terbuka lewat API publik Supabase. Koneksi Npgsql memakai user postgres dan
  tidak terpengaruh RLS.
- Jangan pernah memblok UI thread. Di versi async jangan pakai .Result atau .Wait().
  Pakai Async Sub dan Await.
- Image.FromFile mengunci file. Selalu ambil gambar lewat ModProduk.AmbilGambar (membaca
  lewat stream lalu clone) supaya file bisa diganti.
- Npgsql menolak DateTime ber-Kind UTC untuk kolom timestamp tanpa zona. Kirim
  dtp.Value.Date dan biarkan SQL mengisi waktu.
- Hotkey Ctrl+Alt+F12 bisa gagal terdaftar bila dipakai aplikasi lain. DaftarHotkey
  mengembalikan False, maka siapkan cadangan: klik 5 kali cepat pada logo di pojok
  FrmWelcome membuka login.
- Hapus data yang sudah dipakai di pesanan akan ditolak database (kode 23503). Tangkap
  PostgresException dan tawarkan "Nonaktifkan" sebagai gantinya. Kode duplikat unik
  adalah 23505.
- Di VB, Dictionary dan List dalam modul bersifat shared dan hidup selama aplikasi
  jalan. Bersihkan saat Kosongkan/Keluar supaya data pesanan lama tidak bocor ke
  pelanggan berikutnya.
- Merge besar di akhir adalah sumber masalah terbesar. Merge kecil dan sering.
