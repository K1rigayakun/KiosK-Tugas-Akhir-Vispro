1. RINGKASAN PROYEK
========================================================================================
Aplikasi pemesanan makanan bergaya kiosk MCD/KFC. Dibuat dengan Windows Forms VB.NET
(.NET 10) dan database PostgreSQL di Supabase. Dikerjakan 5 orang secara paralel.

Dua mode aplikasi:
- Mode Kiosk: layar penuh dan selalu di atas. Dipakai pelanggan untuk memilih menu dan
  memesan.
- Mode Staff: jendela MDI. Staf menekan Ctrl+Alt+F12 di kiosk, login, lalu masuk. Isinya
  kasir, dapur, layar antrian, dan admin (produk, voucher, laporan, dashboard, member,
  pengguna, pengaturan, log).

Alur satu pesanan:
1. Pelanggan memilih Dine In atau Take Away, memilih menu, mengatur opsi, lalu
   memasukkan ke keranjang (A2, A3).
2. Checkout: diskon, voucher, pajak, pilih metode bayar. Pesanan disimpan dan mendapat
   nomor antrian (A3).
3. Tunai: status "Menunggu Pembayaran", pelanggan bayar di kasir lalu kasir konfirmasi
   (A4). QRIS/kartu/e-wallet (simulasi): langsung Lunas dan "Diproses" (A3).
4. Dapur melihat pesanan "Diproses" dan menandainya "Siap" (A4).
5. Layar antrian menampilkan nomor yang sedang disiapkan dan yang siap diambil (A4).
6. Pesanan diambil dan menjadi "Selesai". Datanya masuk riwayat dan laporan admin (A5).

Pembagian anggota:
A1  Fondasi, Login, MDI induk, Pengguna, Pengaturan, integrasi akhir
A2  Kiosk pelanggan: Welcome, Menu, Detail Produk, idle, rating
A3  Keranjang, Checkout, Pembayaran, Struk
A4  Kasir, Dapur, Layar Antrian, Log aktivitas
A5  Admin: Produk, Voucher, Laporan, Dashboard, Member

Nama: A1 ____________  A2 ____________  A3 ____________
      A4 ____________  A5 ____________

Materi wajib: repo https://github.com/rezaaplvv/Pemograman-Visual, yaitu Pertemuan 1-8,
11 (Windows API), dan 12 (Menu MDI). Repo itu hanya referensi, jangan di-push ke sana.
Pertemuan 9 dan 10 tidak ada di repo, jadi tidak dihitung. Kalau dosen ternyata
mewajibkannya, kabari tim. README repo punya "Kamus Sintaks" yang berguna sebagai
contekan.

Materi adalah syarat MINIMAL. Semua orang wajib memenuhinya dulu. Pengembangan di atas
materi ada di bagian 7 dan dikerjakan setelah bagian minimal milikmu jalan.

Syarat minimal setiap anggota:
- Punya minimal satu form dan satu modul sendiri.
- Punya minimal satu query ke Supabase yang berparameter.
- Validasi input dengan ErrorProvider dan TryParse.
- Penanganan error dengan Try/Catch (dan Finally bila perlu).
- Dokumentasi berformat repo materi: deskripsi, tabel kontrol, kode, pembahasan,
  kesimpulan.

2.1 Peranmu

Kamu memegang bagian uang: keranjang, perhitungan harga, pembayaran, penyimpanan
pesanan, dan struk. Ketepatan hitungan dan kebenaran data pesanan adalah prioritas,

2.2 Form dan modul yang kamu bangun (wajib)
-------------------------------------------
ModKeranjang (Modul): kontraknya ada di bagian 6.4 dan disepakati dengan A2 di hari
pertama.
- Isi di dalam boleh Dictionary(Of String, ItemKeranjang) dengan Kunci sebagai key,
  asalkan kontrak luar tidak berubah.
- Tambah menggabungkan qty bila Kunci sama (produk, opsi, dan catatan sama). Setiap
  perubahan memicu event KeranjangBerubah.
- Kosongkan juga mengosongkan voucher dan data member sementara.
- Fase 1: isi keranjang dengan item contoh saat debug supaya FrmKeranjang bisa
  dikerjakan tanpa menunggu A2.

FrmKeranjang (Forms/Checkout)
- Kontrol: dgvKeranjang (bsKeranjang), tombol + dan - serta btnHapus, pnlUpsell
  (FlowLayoutPanel), txtVoucher, btnPakaiVoucher, txtNoHpMember dan btnCariMember (untuk
  butir 12), lblSubtotal, lblDiskon, lblPajak, lblTotal, btnLanjutBayar, btnKembaliMenu,
  errKeranjang.
- Ubah qty lewat tombol atau edit sel (TryParse, rentang 1-20). Qty 0 meminta konfirmasi
  hapus. Hapus item selalu dengan konfirmasi Yes/No.
- Ringkasan dihitung lewat ModPromo.HitungRincian, tampil dalam Rupiah (ModFormat).
- Diskon bertingkat (If/ElseIf dengan AndAlso/OrElse): subtotal >= Rp100.000 diskon 5%,
  >= Rp200.000 diskon 10%, >= Rp300.000 diskon 15%. Angka ini contoh, tulis sebagai
  konstanta di ModPromo supaya mudah diubah.
- Voucher: ModPromo.CekVoucher meng-query tabel voucher (berparameter). Valid bila
  aktif, tanggal hari ini dalam rentang tgl_mulai dan tgl_akhir, dan subtotal >=
  min_belanja. Pesan penolakan harus spesifik (kadaluarsa, belum mulai, kurang belanja,
  tidak ditemukan). HashSet(Of String) mencegah voucher yang sama dipakai dua kali pada
  satu pesanan.
- Upsell: saat Lanjut Bayar ditekan dan keranjang belum punya produk kategori Minuman
  atau Side Dish, tampilkan pnlUpsell berisi 3 produk saran (For Each, HashSet(Of
  Integer) untuk menyaring produk yang sudah ada di keranjang). Tombol "Tambah"
  memasukkan dengan opsi bawaan, tombol "Lewati" lanjut. Upsell hanya muncul sekali per
  pesanan.
- Pajak default 11% dari ModPengaturan "pajak_persen", dihitung dari (subtotal dikurangi
  total diskon). Total diskon dibatasi maksimal 50% subtotal dan total tidak boleh
  negatif.

FrmPembayaran (Forms/Checkout)
- Kontrol: rdoTunai, rdoQris, rdoKartu, rdoEWallet, lblTotal, txtUangBayar,
  lblKembalian, lstPecahan, pnlSimulasi, btnBayar, btnKembali, errBayar.
- Tunai: pesanan disimpan dengan status "Menunggu Pembayaran" dan status bayar "Belum".
  Layar menampilkan nomor antrian dan arahan "Silakan bayar di kasir". Pelanggan boleh
  mengisi uang yang akan dibayar untuk melihat estimasi kembalian: KeyPress hanya angka,
  TryParse, harus >= total (ErrorProvider), tampilkan lewat HitungKembalian dan
  PecahKembalian.
- PecahKembalian memakai Do-Loop dari pecahan terbesar ke terkecil. Fungsi ini juga
  dipakai A4 di FrmKasir.
- QRIS, Kartu, E-Wallet (simulasi): tampil panel simulasi. Kartu: tombol "Tempel kartu"
  dengan ProgressBar 2 detik (Timer). Setelah berhasil, pesanan disimpan langsung Lunas
  dan Diproses.
- Seluruh proses simpan dibungkus Try/Catch. Bila gagal, tampilkan pesan ramah dan
  jangan kosongkan keranjang.

FrmStruk(idPesanan, Optional cetakUlang) (Forms/Checkout)
- Kontrol: txtStruk (TextBox multiline ReadOnly, font Courier New), btnSimpan, btnCetak
  (butir 6), picQr (butir 6), btnSelesai.
- Isi struk dibangun dari query pesanan dan detail_pesanan dengan For Each dan
  StringBuilder: lebar tetap 32-40 kolom, PadRight dan PadLeft untuk rata kiri-kanan,
  nomor antrian besar, tipe makan, tanggal, item, subtotal, diskon, pajak, total, metode
  bayar, dan kembalian bila ada.
- Simpan .txt: SaveFileDialog lalu StreamWriter dalam Using dengan Try/Catch
  (IOException) dan Finally.
- Selesai: buka FrmRating (A2) lalu ModKeranjang.Kosongkan dan DialogResult.OK. Pada
  mode cetakUlang = True, tombol Selesai hanya menutup form (tanpa rating dan tanpa
  mengosongkan keranjang).

ModPesanan (Modul)
- SimpanPesanan, HitungKembalian, PecahKembalian (bagian 6.4). Versi minimal: INSERT
  pesanan dengan RETURNING id_pesanan lewat EksekusiScalar, lalu loop INSERT
  detail_pesanan. Nomor antrian dihitung per hari WIB.
- Butir 3 meningkatkannya menjadi transaksi atomik.

ModPromo (Modul)
- CekVoucher dan HitungRincian (bagian 6.4). Satu pintu untuk semua hitungan harga.
- Urutan: diskon bertingkat dan diskon voucher dihitung dari subtotal, lalu diskon poin
  member, total diskon dibatasi 50% subtotal, kemudian pajak dari (subtotal - total
  diskon), lalu total.
- Voucher Persen dihitung dari subtotal (bukan setelah diskon bertingkat).
- Contoh uji 1: subtotal 250.000, diskon bertingkat 10% = 25.000, voucher HEMAT10 =
  25.000, total diskon 50.000, pajak 11% x 200.000 = 22.000, total 222.000.
- Contoh uji 2: subtotal 90.000, tanpa diskon bertingkat, voucher POTONG5K = 5.000,
  pajak 11% x 85.000 = 9.350, total 94.350.
- Tulis kedua contoh itu sebagai uji manual di Dokumentasi.

2.4 Pengembangan milikmu (butir 3, 6, 10, 11)
---------------------------------------------
#3 Transaksi atomik pesanan (P1)
- Di ModPesanan.SimpanPesanan: Using conn = ModDatabase.BukaKoneksi(), Using trx =
  conn.BeginTransaction(). Langkah di dalam satu transaksi:
  1. Hitung nomor antrian: SELECT COALESCE(MAX(no_antrian),0)+1 FROM pesanan WHERE
     tanggal::date = (now() at time zone 'Asia/Jakarta')::date.
  2. INSERT pesanan ... RETURNING id_pesanan (tanggal diisi default WIB, jangan kirim
     dari aplikasi).
  3. Loop INSERT detail_pesanan (simpan nama_produk dan harga_satuan sebagai salinan
     saat itu).
  4. Kurangi stok (butir 7): untuk tiap item, SELECT stok FROM produk WHERE id_produk =
     @id FOR UPDATE. Bila stok NULL, lewati. Bila stok kurang dari qty, Rollback dan
     beri pesan "Stok <nama> tidak cukup". Bila cukup: UPDATE produk SET stok = stok -
     @qty, tersedia = (stok - @qty > 0) WHERE id_produk = @id.
  5. Bila ada member (butir 12): UPDATE member SET poin = poin - @dipakai + @didapat
     WHERE id_member = @id.
  6. Commit. Exception apa pun: Rollback di Catch lalu lempar ulang.
- Bentrok nomor antrian (PostgresException dengan SqlState 23505 pada
  ux_pesanan_antrian_harian): ulangi seluruh transaksi maksimal 3 kali.
- Setelah commit, panggil ModCache.HapusAwalan("produk") karena stok berubah.

#6 Struk cetak dengan QR (P1)
- Tambahkan paket QRCoder. PASANG DAN COBA SEJAK AWAL karena belum diuji di .NET 10.
  Bila bermasalah, kabari A1 dan lanjutkan tanpa QR (struk tetap sah).
- QR berisi teks sederhana, contoh "PESANAN-{id}-{no_antrian}". Tampilkan di picQr dan
  gambar juga di struk cetak.
- Cetak memakai PrintDocument dan PrintPreviewDialog. Handler PrintPage menggambar teks
  (Graphics.DrawString, font Courier New) dan QR (DrawImage). PrintDocument tidak ada di
  materi, jadi ini bonus, bukan pengganti simpan .txt.

#10 Mesin promo (P2)
- Rapikan ModPromo.HitungRincian supaya semua aturan ada di satu tempat: bertingkat,
  voucher, poin, batas diskon 50%, pajak. Tampilkan rincian per baris di FrmKeranjang
  dan di struk (diskon bertingkat, diskon voucher, diskon poin, pajak, total).
- Pindahkan angka ambang diskon bertingkat ke ModPengaturan bila sempat.

#11 Simulasi QRIS (P2)
- Di FrmPembayaran, pilih QRIS: tampilkan QR (QRCoder) berisi teks simulasi
  "QRIS-SIMULASI|{total}|{kode acak}". Hitung mundur 2 menit memakai Timer dan
  ModFormat.Durasi. Tombol "Simulasi Sudah Bayar" menyelesaikan pembayaran, tombol Batal
  kembali ke pilihan metode. Bila waktu habis, kembali ke pilihan metode tanpa menyimpan
  pesanan. Ini simulasi, bukan pembayaran sungguhan.

4.2 Konvensi
------------
- Teknologi: VB.NET, Windows Forms, target net10.0-windows, format solution .slnx.
  Option Strict On diatur di .vbproj oleh A1. Paket NuGet: Npgsql dan
  Microsoft.Extensions.Configuration.Json. Satu-satunya paket tambahan untuk
  pengembangan adalah QRCoder (dipakai A3). Samakan versi Visual Studio dan SDK .NET
  dengan yang dipakai di materi.
- Prefix kontrol dari materi: btn, txt, lbl, cbo, dgv, lst, bs, err, pic, chk, tmr.
  Tambahan yang disepakati: pnl, flp, tab, mnu, nud, dtp, rdo, grp.
- Form berawalan Frm, modul berawalan Mod. Class model memakai PascalCase tanpa prefix.
- Class model memakai Public Property, bukan field public.
- Modul data dan modul hitung tidak menampilkan MessageBox. Error dilempar ke pemanggil,
  lalu form yang menangkapnya dengan Try/Catch dan menampilkan pesan ramah.
- Semua query berparameter. Parameter dikirim lewat Dictionary(Of String, Object) dengan
  kunci tanpa tanda @. Dilarang menyambung input pengguna langsung ke teks SQL.
- Pesan ke pengguna memakai Bahasa Indonesia yang singkat dan jelas. Jangan tampilkan
  stack trace ke pelanggan.
- Format uang selalu lewat ModFormat.Rupiah. Status, metode bayar, dan peran selalu
  lewat class konstanta, jangan menulis string manual.
- Waktu: kolom waktu pesanan disimpan dalam WIB oleh SQL, yaitu (now() at time zone
  'Asia/Jakarta'). Server Supabase memakai UTC, jadi tanpa ini nomor antrian dan laporan
  harian akan salah jam. Jangan kirim DateTime.Now atau DateTime.UtcNow ke kolom waktu
  pesanan. Untuk filter tanggal dari DateTimePicker kirim dtp.Value.Date.
- Saat debug (Debugger.IsAttached), jangan aktifkan TopMost dan layar penuh supaya
  Visual Studio tetap bisa dipakai.
- Jangan mengedit file .Designer.vb dengan tangan kecuali terpaksa.
- Event handler dibuat pendek. Query dan perhitungan ditaruh di modul.

12. RISIKO DAN TIPS
========================================================================================
- Project Supabase paket Free dijeda otomatis kalau aktivitas database terlalu sedikit
  selama seminggu. Pastikan project aktif sebelum demo. Simpan skema.sql dan seed.sql
  supaya database bisa dibuat ulang dengan cepat.
- Koneksi dari rumah bisa gagal karena koneksi langsung Supabase biasanya hanya IPv6.
  Pakai connection string "Session pooler" dari dashboard (menu Connect). Bukan
  "Transaction pooler".
- Password database milik repo materi sudah terlanjur terbuka di repo publik. Jangan
  dipakai ulang. Sebaiknya beri tahu pemilik repo untuk me-reset password-nya.
- Aktifkan RLS (Row Level Security) di semua tabel tanpa membuat policy, supaya tabel
  tidak terbuka lewat API publik Supabase. Koneksi Npgsql memakai user postgres dan
  tidak terpengaruh RLS.
- Jangan pernah memblok UI thread. Di versi async jangan pakai .Result atau .Wait().
  Pakai Async Sub dan Await.
- Image.FromFile mengunci file. Selalu ambil gambar lewat ModProduk.AmbilGambar (membaca
  lewat stream lalu clone) supaya file bisa diganti.
- Npgsql menolak DateTime ber-Kind UTC untuk kolom timestamp tanpa zona. Kirim
  dtp.Value.Date dan biarkan SQL mengisi waktu.
- Hotkey Ctrl+Alt+F12 bisa gagal terdaftar bila dipakai aplikasi lain. DaftarHotkey
  mengembalikan False, maka siapkan cadangan: klik 5 kali cepat pada logo di pojok
  FrmWelcome membuka login.
- Hapus data yang sudah dipakai di pesanan akan ditolak database (kode 23503). Tangkap
  PostgresException dan tawarkan "Nonaktifkan" sebagai gantinya. Kode duplikat unik
  adalah 23505.
- Di VB, Dictionary dan List dalam modul bersifat shared dan hidup selama aplikasi
  jalan. Bersihkan saat Kosongkan/Keluar supaya data pesanan lama tidak bocor ke
  pelanggan berikutnya.
- Merge besar di akhir adalah sumber masalah terbesar. Merge kecil dan sering.
